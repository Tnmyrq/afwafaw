# Лендинг программ питания

Одностраничный сайт по ТЗ из `ПРОМПТ.txt`: mobile-first, без фреймворков и тяжёлых библиотек.
Блоки идут в порядке ТЗ: первый экран → программы → калькулятор → плюсы → фото → отзывы → FAQ → форма → подвал.
Отдельно собираются страницы «Политика конфиденциальности» и «Оферта».

Сейчас включён **демо-режим**. Цены, отзывы, цифры, контакты и фото в нём — примеры, их нужно заменить на данные заказчика. Сверху висит жёлтая плашка, индексация закрыта, форма имитирует отправку.

## Структура

```
content/content.json        ← ВСЕ тексты, цены, отзывы, FAQ, фото, контакты, ID аналитики
content/legal/*.html        ← тексты политики и оферты (шаблоны, проверить у юриста)
src/styles.css              ← стили (при сборке встраиваются в HTML)
src/main.js                 ← логика: форма, маска телефона, калькулятор, галерея, аналитика, cookie
src/assets/img/             ← изображения (сейчас заглушки)
api/lead.js                 ← обработчик заявок для Vercel (serverless): Telegram, CRM-вебхук
vercel.json, package.json   ← настройки сборки и деплоя на Vercel
server/send.php             ← альтернативный обработчик для обычного хостинга с PHP
server/send.config.example.php ← образец настроек PHP-обработчика
server/.htaccess            ← HTTPS, сжатие, кэширование (для Apache)
tools/images.py             ← подготовка реальных фото (WebP 1200 + 600 px)
tools/make-placeholders.py  ← генерация заглушек (для демо)
build.js                    ← сборка: content + src → dist/
dist/                       ← готовый сайт, эту папку загружают на хостинг
```

## Запуск и сборка

Нужен только Node.js 18+, других зависимостей нет.

```powershell
node build.js --serve
```

Сайт откроется на http://localhost:8080. Чтобы только собрать сайт без сервера, запустите `node build.js`.
После каждой сборки скрипт выводит список того, что ещё не заполнено перед запуском.

## Как обновить контент без разработчика

1. Откройте `content/content.json` в любом редакторе (например, в VS Code или прямо в веб-интерфейсе GitHub).
2. Поменяйте текст в кавычках. Кавычки, запятые и скобки не трогайте.
3. Сохраните изменения в GitHub (через `git push` или кнопку **Commit changes** в веб-интерфейсе). Vercel сам пересоберёт и опубликует сайт через 1–2 минуты.

| Что поменять | Где в content.json |
|---|---|
| Название, title и description для поиска | `site` |
| Телефон, Telegram, WhatsApp, соцсети | `contacts` |
| ИП/ООО, ИНН, адрес | `company` |
| Заголовок первого экрана (до 8 слов) | `hero.title` |
| Строка «N лет · N клиентов · N отзывов» | `hero.trust`. Пустой список `[]` скрывает строку |
| Программы, цены, состав, бейдж «Популярно» | `programs.items` (`popular: true`) |
| Показывать калькулятор или нет | `calculator.enabled` |
| Наши плюсы | `benefits.items` (иконки: chef, heart, clock, chat, swap, leaf) |
| Фото еды | `gallery.items`: `src` для превью, `full` для просмотра на весь экран, `alt` — описание блюда |
| Отзывы | `reviews.items`. `result` заполняйте только подтверждённым результатом, `photo` — только с согласия автора |
| Вопросы и ответы | `faq.items` |
| Срок ответа «свяжемся в течение N часов» | `form.responseHours` |

### Фото

Положите фото блюд в любую папку и выполните:

```powershell
python tools/images.py C:\путь\к\фото
```

Скрипт создаст `src/assets/img/food/01.webp` (1200 px) и `01-sm.webp` (600 px, квадрат). Фото для первого экрана готовится так:

```powershell
python tools/images.py --hero C:\путь\к\фото.jpg
```

Нужен Python с Pillow (`pip install pillow`). Другой вариант — конвертировать фото в WebP вручную на squoosh.app.
Картинка для превью ссылок `src/assets/img/og.jpg` имеет размер 1200×630, её можно заменить на свою.

## Деплой на Vercel

Проект уже настроен (`vercel.json`): Vercel выполняет `node build.js`, раздаёт папку `dist/`, а заявки принимает функция `api/lead.js` по адресу `/api/lead`. HTTPS и сжатие Vercel включает сам.

1. На vercel.com нажмите **Add New → Project** и импортируйте этот репозиторий с GitHub. Framework Preset: **Other**. Остальные поля Vercel возьмёт из `vercel.json`, их менять не нужно.
2. В **Settings → Environment Variables** добавьте переменные:

   | Переменная | Значение |
   |---|---|
   | `TELEGRAM_BOT_TOKEN` | токен бота от @BotFather |
   | `TELEGRAM_CHAT_ID` | id группы менеджеров (начинается с `-100…`, можно узнать через @getmyid_bot). Бота нужно добавить в группу |
   | `TELEGRAM_THREAD_ID` | необязательно: id темы, если в группе включены темы |
   | `WEBHOOK_URL` | необязательно: адрес CRM, Make или n8n — туда уйдёт JSON заявки |
   | `SITE_URL` | необязательно: `https://ваш-домен.ru`. Без неё ссылки для превью ведут на домен `*.vercel.app` |
   | `ALLOWED_ORIGINS` | необязательно: `https://ваш-домен.ru,https://www.ваш-домен.ru` |

3. Нажмите **Redeploy**. Когда заданы `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` (или `WEBHOOK_URL`), сборка сама подключает форму к `/api/lead`. Без них форма только имитирует отправку.
4. Подключите свой домен в **Settings → Domains**.
5. После этого каждый `git push` в ветку `main` публикует сайт автоматически, а для других веток Vercel создаёт превью-ссылки.

Email из функции не отправляется: на Vercel нет `mail()`. Если заявки нужны на почту, передайте их через `WEBHOOK_URL` (Make, n8n, Zapier).
Ограничение частоты в функции работает в памяти одного инстанса, поэтому это только базовая защита. Основную работу делают honeypot, проверка времени заполнения и лимит в браузере.
Заранее проверьте, как сайт открывается с российских мобильных операторов: доступность зарубежных хостингов в РФ бывает нестабильной. Свой домен обычно помогает.

## Запуск в продакшн: чек-лист

1. В `content.json` поставьте `"demo": false`. Это уберёт плашку и откроет сайт для индексации (robots.txt, sitemap.xml).
2. Укажите адрес сайта: `site.url` в `content.json` или переменную `SITE_URL` в Vercel. От него зависят Open Graph и sitemap.
3. Заполните `contacts` и `company`, замените фото, отзывы и цены на реальные.
4. Подключите форму через переменные окружения Vercel (см. выше).
5. Аналитика: укажите `analytics.yandexMetrikaId` (и/или `ga4Id`, `vkPixelId`, `metaPixelId`). В Метрике создайте цели типа «JavaScript-событие» с идентификаторами из таблицы ниже.
6. Проверьте превью ссылки: отправьте адрес боту @WebpageBot в Telegram, он обновит кэш превью.
7. Прогоните Lighthouse (Chrome DevTools → Lighthouse → Mobile) и чек-лист приёмки из раздела 10 ТЗ на реальных устройствах.

### Альтернатива: обычный хостинг с PHP

Для Beget, Timeweb, REG.RU и подобных хостингов:

1. В `content.json` впишите `"form": { "endpoint": "send.php", ... }`.
2. Скопируйте `server/send.config.example.php` в `server/send.config.php`, заполните токен бота и chat_id. Этот файл в git не попадает.
3. Выполните `node build.js` и загрузите содержимое `dist/` на хостинг: `send.php` и `.htaccess` попадут туда автоматически.

## Цели аналитики

| Идентификатор | Когда срабатывает |
|---|---|
| `cta_primary` | клик по главной кнопке «Подобрать программу» |
| `cta_sticky` | клик по липкой кнопке «Записаться» |
| `programs_view` | пользователь доскроллил до тарифов |
| `program_select` | нажал «Выбрать» в карточке программы |
| `calc_use` | получил результат в калькуляторе |
| `calc_cta` | нажал «Получить план питания» |
| `form_open` | форма появилась на экране |
| `form_submit` | заявка успешно отправлена |
| `telegram_click` / `whatsapp_click` | переход в мессенджер |
| `gallery_open` | открыл фото на весь экран |

UTM-метки из ссылки сохраняются на время сессии, уходят в заявку скрытыми полями и передаются в Метрику как параметры визита.
Если `analytics.requireConsent: true`, счётчики загружаются только после нажатия «Принять» в cookie-баннере.

## Что сделано и проверено

- Вёрстка mobile-first. На ширинах 360, 375 и 1440 px нет горизонтального скролла. Все кнопки не ниже 48 px, шрифт в полях 17 px, поэтому iOS не увеличивает страницу при фокусе.
- Липкая кнопка «Записаться» появляется после первого экрана. Она прячется, когда видна форма и когда открыта клавиатура. Поле в фокусе прокручивается выше клавиатуры.
- Калькулятор считает по формуле Миффлина — Сан Жеора и сходится с контрольными примерами ТЗ: 1780 / 2759 ккал и 1330 / 1829 ккал.
- Форма: валидация под полями, маска +7 (включая ввод с «8», вставку и автозаполнение), состояние загрузки, экран успеха. Выбранная программа, результат калькулятора и UTM передаются скрытыми полями.
- Защита от спама: honeypot, минимальное время заполнения, ограничение частоты на клиенте и на сервере по IP. Капчи нет.
- Галерея открывает фото на весь экран: свайп влево и вправо, свайп вниз закрывает, работают стрелки, Esc и кнопка «Назад» на Android.
- SEO: title, description, один H1, alt у всех изображений, Open Graph 1200×630, favicon, sitemap.xml, robots.txt.
- Учитывается `prefers-reduced-motion`. Шрифты Manrope и Unbounded подключены с кириллицей и не блокируют отрисовку.

- Функция `api/lead.js` проверена в локальной имитации Vercel. Правильная заявка уходит в вебхук целиком, с кириллицей, программой, комментарием и UTM. Ошибки валидации возвращают 422, спам отбрасывается, повторная отправка даёт 429.

**Не проверено:** реальный деплой на Vercel и доставка в Telegram (нужен токен бота), Lighthouse, реальные iPhone и Android, встроенные браузеры Telegram, Instagram и VK, работа `send.php` (локально PHP не установлен). Это нужно сделать на этапе 5 «Тестирование».

**Вне кода:** макеты в Figma (375 и 1440 px) по ТЗ сдаются отдельно.

## Юридические замечания

- Политика и оферта — шаблоны. Перед запуском их должен проверить юрист.
- Instagram принадлежит Meta, деятельность которой запрещена в РФ. В подвале при наличии ссылки на Instagram автоматически выводится обязательная сноска. Подключать Meta Pixel не рекомендуется.
- Отзывы публикуются только реальные и с согласия авторов. Результат указывается только подтверждённый.
- Формулировки на сайте избегают гарантий («помогает», «ориентировочно»). Дисклеймер о том, что программы не заменяют медицинскую помощь, есть в FAQ и в подвале.

## Вопросы заказчику (раздел 12 ТЗ)

1. Название, логотип, фирменные цвета? Сейчас используется рабочее название «ВкусБаланс» и палитра из ТЗ.
2. Точные цены и состав программ? Что входит в «Баланс»: сбалансированное питание или поддержание веса?
3. Есть ли фото блюд (нужно минимум 8), фото команды и отзывы с согласием авторов?
4. Куда отправлять заявки: Telegram-бот, группа менеджеров, CRM или email?
5. Оставляем калькулятор калорий? Сейчас он включён.
6. Есть ли домен, хостинг (поддерживается ли PHP) и счётчик Метрики?
7. Планируется ли реклама? От этого зависит подключение VK Pixel.
8. Тон общения? Сейчас тексты дружелюбные, на «вы».
9. Срок запуска, бюджет, время доставки и город?
